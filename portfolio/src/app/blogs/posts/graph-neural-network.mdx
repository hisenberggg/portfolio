# Graph Neural networks

In an era marked by great technological advancements and the exponential growth of artificial intelligence, the utilization of graph structures for data storage has skyrocketed. There has also been substantial progress in algorithms and techniques for processing this data. In this article, we’ll explore Graph Neural Networks (GNNs), a revolutionary approach tailored for processing complex, graph-structured data.

## Graphs
Before starting, let’s quickly revise the features of a graph.

- A Graph is the type of data structure that contains nodes and edges.
- A node can be any entity (person, place, things, etc.), and the edges define the relationship between nodes <a href="https://www.geeksforgeeks.org/what-is-the-difference-between-an-undirected-and-a-directed-graph/">(Directed / Undirected)</a>.

![image](../../../../images/blogs/gnn/grapheg.png)
*Representation of a Graphical Data* 

**Where do we find graphical data in real world?**

- Recommendation System — social media / E-commerce platforms, where the users are interconnected by a relationship.
- Biological Networks — Biological entities like proteins or genes are the node and interactions or relationships between these entities are the edges.
- Computer Networks — LANs: Each machine is a node, and the communication links between these devices are the edges.

**What real world problems can we solve with Graphical data and GNN?**

- Recommendation System — Potential linkages between users can be predicted, Users can be clustered into groups by learning their behavioral patterns.
- Biological Networks — Predicting a cancerous molecule by analyzing the patterns in its network or detecting an abnormal edge within the molecule.
- Computer Networks — Predict future network traffic patterns, detect anomalies or unusual activities in the network or to optimize network routing.

## GNN
As we know, Convolutional Neural Networks (CNNs) excel at handling spatial data (Images and videos), while Recurrent Neural Networks (RNNs) are specialized for sequential data (Time series, Text). Similarly, Graph Neural Network (GNN) are the special type of neural networks that are highly proficient at processing and analyzing graphical data.

Graph neural networks (GNNs) were first proposed by <a href="https://doi.org/10.1109/IJCNN.2005.1555942">Gori and Scarselli</a> in 2005, but only recently have they begun to gain traction. The implementation of GNNs ranged from recommendation systems in social networking platforms like Facebook & twitter, to storing knowledge base in graphical structure called Knowledge graphs.

**But what was the need of introducing a new form of neural network? Can’t the traditional neural networks or CNNs, process Graphical data?**

Traditional neural networks are adept in working with Euclidian data (Text & Image), and Euclidean data is something which can be represented in Euclidean space.

In simple terms, graph is not a type of Euclidean data and thus, it cannot be processed using traditional neural networks.

Refer to the below section in order to understand it in detail.

<hr/>

> <a href="https://www.britannica.com/science/Euclidean-space">Euclidean Space</a> — A space in any finite number of dimensions, in which points are designated by coordinates (one for each dimension) and the distance between two points is given by a distance formula. This concept primarily pertains to flat surfaces and emphasizes geometric relationships and positional accuracy i.e. Coordinates.

![Euclidean space](../../../../images/blogs/gnn/euc_space.jpg)

**But why is Graph not a Euclidean data structure? A graph can be represented in a 2D/3D space, right?** 🤔

Well, it’s not that straight forward. Here’s the tea:

Graph focuses on the nodes and the relationships, rather than specific geometric positions in a 2D/3D plane. So, representing it in a coordinate plane doesn’t make much sense as it will lead to distortions.

Example: — Two nodes positioned close to each other in a 3D Euclidean space might suggest a close relationship. However, the actual closeness of the nodes should be based on the strength or quality of their relationship.

In a Euclidean space, the shortest path between two nodes is simply a straight line connecting them. However, in a graph, the shortest path is determined by the aggregation of the weights of the edges along the path, rather than just the direct geometric distance.

**Okay, but an image is also a graph of connected pixels, then a CNN should be able to process it, right?**

NO! An image is topologically uniform graph of pixel. However, the graphs we discussed in above examples will NOT be uniform.

To understand it better, have a look at how CNN works on an image.

![CNN](../../../../images/blogs/gnn/conv.gif)

Consider the 5x5 grid as an image. While processing images via CNNs, we slide the convolutional operator window (3x3 yellow grid) across a two-dimensional image, and we compute some function over that sliding window. Then, we pass it through many layers (pooling layer, dropout layer, etc.). Now imagine, sliding a fixed sized window on an undefined and complex topology of graphs, such as our Recommendation system above. An absolute nightmare!

## GNN use cases
Now that we know what the graph data is, let’s hop on to the problems that a GNN can solve.

Broadly these problems are divided into 3 categories:

1. **Graph level**: Goal is to identify property of the entire graph. Assuming the analogy of an image as a graph of connected pixels, classify the whole image to determine whether it is a cat or a dog. Similarly, if we consider our recommendation system graph, it can be classified into a friend network (Instagram) or professional relationship network (LinkedIn).
2. **Node level**: Focus is on predicting the identity or role of each node within a graph based on local and global context. For instance, in our recommendation system we can cluster various nodes (users) based on the closeness. We can even use it for classifying the users as spam or not spam.
![nodelevel](../../../../images/blogs/gnn/nodelevel.png)
3. **Edge level**: Focus is on making predictions or classifications for edges within a graph. For example, predicting the future connection and potential network within a social media/E-com recommendation.
![edgelevel](../../../../images/blogs/gnn/edgelevel.png)

## GNNs and Embeddings
A GNN can be broadly used to learn a representation of the nodes in a graph. These representations are known as Node embeddings, Edge embeddings and Graph embeddings.

> **What are Embedding?** Embeddings can be defined as the mathematical representation of discrete objects that encode semantic and contextual information in a compact and meaningful way, allowing machine learning algorithms to effectively analyze and understand the data.

We can think of an embedding as a function that takes an input (such as a node in a graph) and outputs a vector of numbers. These embeddings are then used to map the graph in a lower dimension embedding space, so that similar nodes in the graph are embedded close to each other. For example, we can map a 3D vector to a 2D vector.

![mapping](../../../../images/blogs/gnn/mapping.png)
*The node u & v are encoded and mapped into embedding space [<a href="https://medium.com/the-modern-scientist/graph-neural-networks-series-part-3-node-embedding-36613cc967d5">source</a>]*

Thus, assigning attributes to nodes helps generate accurate and comprehensive embeddings.

If you’re familiar with Machine Learning, you likely know that embeddings are commonly used in a wide range of tasks. Thus, it offers a major advantage over other methods, as it can be trained using standard neural network optimization techniques.

## Implementing GNN for Node Classification
For this problem, we can arbitrarily consider our Recommendation system graph, with the data being augmented to thousands of nodes (users) and edges (relationships).

Now we can classify the users that have inclination towards a certain category of products. We will use the Deep Graph Library (DGL) to build and train our model. We can directly import the NetworkX graph into DGL.
```python
import dgl

g = dgl.from_networkx(G)
```

**Model building**: There are various types of GNNs, like Graph Convolutional Network, Message Passing Neural Network, Graph Attention Network. For this use case, we’ll be using <a href="https://tkipf.github.io/graph-convolutional-networks/">Graph Convolutional Network (GCN)</a>.

Building GCN is similar to building a CNN, except for the pooling layers. We can build a simple GCN using inbuilt <a href="https://docs.dgl.ai/en/latest/generated/dgl.nn.pytorch.conv.GraphConv.html">GraphConv</a> layer offered by DGL and <a href="https://www.geeksforgeeks.org/activation-functions/">Relu</a> as our activation function.
```python
from dgl.nn import GraphConv
import torch
import torch.nn as nn
import torch.nn.functional as F

class GCN(nn.Module):
    def __init__(self, in_dim, hidden_dim, output_dim):
        super(GCN, self).__init__()
        self.conv1 = GraphConv(in_dim, hidden_dim)
        self.conv2 = GraphConv(hidden_dim, output_dim)

    def forward(self, g, in_dim):
        h = self.conv1(g, in_dim)
        h = F.relu(h)
        h = self.conv2(g, h)
        return h
```

**Training and optimization**: As mentioned earlier, we can use standard neural network optimization algorithms when working with embeddings. For simplicity, we’ll use gradient descent as the optimization algorithm.

The standard steps for gradient descent optimization go like-
```Text
Get features & labels from the graph

for n epochs:
  Forward pass - compute model predictions using features
  compute loss by comparing predictions with actual labels 
  Backpropagate - optimize
```

In each epoch, our main aim is to first compute the predictions using the model weights. Then compute the loss, by comparing the predictions with actual value using a loss function. Lastly, back-propagation step is to optimize our model weights so the loss is reduced in the next epochs. Hence when the loss is reduced, the accuracy of the model increases.

We’ll use <a href="https://www.geeksforgeeks.org/what-is-cross-entropy-loss-function/">Cross entropy</a> as our loss function and <a href="https://www.geeksforgeeks.org/adam-optimizer/">Adam Optimizer</a> for back propagation task. Cross Entropy calculates loss between the prediction (p) and actual label (q) using the following equation:

```
-(ylog(p) + (1 - y)log(1 - p))
```
To know more about gradient descent, refer to this video by 3Blue1Brown — <a href="https://youtu.be/IHZwWFHWa-w">link</a>
